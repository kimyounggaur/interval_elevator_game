# 음정 엘리베이터 — 프롬프트 설계서 v1

작성 2026-11-12 · 짝 문서: `docs/음정엘리베이터_기획서.md`

AI 코딩 도구(Claude Code 기준, Codex에서도 그대로 사용 가능)에 순서대로 붙여 넣어 앱을 완성하는 지시문 모음이다. 15단계 + 선택 2단계.

## 사용법

1. 0단계(직접 하는 일)를 마친 뒤 1단계부터 차례로 진행한다. 단계를 건너뛰지 않는다.
2. 각 단계의 **프롬프트** 상자 내용을 그대로 복사해 붙여 넣는다.
3. AI가 끝났다고 하면 **확인 방법**대로 직접 화면을 본다. 화면을 보려면 "개발 서버 켜 줘"라고 입력하고, 알려 주는 주소(보통 `http://localhost:3000`)를 브라우저로 연다.
4. 확인이 끝나면 "이 단계 커밋해 줘"라고 입력해 저장 지점을 만든다. 문제가 생기면 이 지점으로 되돌릴 수 있다.
5. 확인이 안 되면 맨 아래 **막혔을 때 쓰는 프롬프트**를 쓴다.

모든 단계에 공통으로 적용되는 규칙은 1단계에서 `CLAUDE.md`(Claude Code)와 `AGENTS.md`(Codex)에 적어 두므로 매번 다시 말하지 않아도 된다.

## 0단계 — 폴더 준비 (직접 하는 일)

1. 작업할 새 폴더를 만든다. 예: `음정엘리베이터` 대신 영어 이름 `interval-elevator`를 권장(일부 도구가 한글 경로에서 오류를 낸다).

   ```
   interval-elevator/
     _kit/
       README.md
       docs/   (기획서, 프롬프트 설계서, prototype.html)
       src/    (engine/, assets/)
       scripts/
   ```
3. `interval-elevator` 폴더에서 Claude Code(또는 Codex)를 연다.

## 1단계 — 프로젝트 만들기

**프롬프트**
```text
이 폴더에 음정 학습 게임 「음정 엘리베이터」 웹앱 프로젝트를 만들어 줘.

1) _kit 폴더는 내가 받은 자료야. 지우거나 고치지 말고 복사만 해.
2) Next.js 15 (App Router, src 폴더, TypeScript, Tailwind CSS, ESLint)로 만들어. npx create-next-app@15 를 써.
   create-next-app이 빈 폴더를 요구하면 임시 폴더에 만든 뒤 이 폴더로 옮겨.
3) 패키지 추가: zustand / 개발용: vitest, tsx
4) next.config: output: 'export', trailingSlash: true, images.unoptimized: true
5) package.json scripts에 "test": "vitest run" 추가
6) _kit의 파일을 복사해:
   _kit/docs/*        → docs/
   _kit/src/engine/   → src/engine/
   _kit/src/assets/   → src/assets/
   _kit/scripts/      → scripts/
7) 맨 위 폴더에 CLAUDE.md와 AGENTS.md를 만들고 둘 다 아래 내용을 그대로 적어.

# 음정 엘리베이터 — 작업 규칙
- 기준 문서는 docs/음정엘리베이터_기획서.md. 화면 모양의 기준은 docs/prototype.html (둘러보기 시안).
- src/engine/engine.ts, src/engine/golden/, src/engine/engine.golden.test.ts, scripts/make-golden.ts는 고치지 않는다.
  규칙을 바꿔야 할 것 같으면 고치지 말고 먼저 나에게 이유를 설명하고 묻는다.
- 음정·정답·선택지·힌트·보이기 규칙·안내 문장·별·잠금은 화면 코드에서 직접 계산하지 않고 엔진 함수만 쓴다.
- 음은 문자·임시표·옥타브로 다룬다. MIDI 번호로 음 이름을 만들지 않는다.
- 임시표는 src/assets/music-glyphs.json의 외곽선(SVG)으로 그린다. 𝄫·𝄪 같은 유니코드 글자를 화면에 쓰지 않는다.
- 화면 글자는 한국어 해요체. 맞음·틀림을 색만으로 알리지 않는다(✓·✗와 글자를 함께).
- 폰 세로(390×844, 360×640)가 먼저다. 가로 스크롤 금지. 누르는 것은 44px 이상.
- 서버·로그인·외부 API를 쓰지 않는다. 저장은 localStorage, 읽기·쓰기는 try/catch.
- 정적 내보내기라서 무작위 값(시드)·localStorage는 화면이 브라우저에 뜬 뒤(useEffect)에 만든다.
- 작업이 끝날 때마다 npm test와 npm run build를 돌리고 결과를 알린다.
- 나는 비개발자다. 결과는 무엇이 바뀌었고 화면 어디서 어떻게 확인하는지로 설명한다.

8) 첫 화면(src/app/page.tsx)은 "음정 엘리베이터 — 준비 중" 한 줄만 둬.
9) git 저장소로 만들고 첫 커밋을 해 줘. _kit 폴더는 .gitignore에 넣어.
10) npm run build가 통과하는지 확인하고 결과를 알려 줘.
```

**확인 방법**
- AI가 `npm run build` 성공을 알린다. 폴더에 `docs/`, `src/engine/`, `src/assets/`, `scripts/`, `CLAUDE.md`, `AGENTS.md`가 생겼다.
- "개발 서버 켜 줘" → 브라우저에서 "음정 엘리베이터 — 준비 중"이 보인다.

## 4단계 — 건반

**프롬프트**
```text
건반 부품 src/components/Keyboard.tsx를 만들어 줘. 기획서 5-8절과 prototype.html의 건반을 따른다.
- props: base, upper, range([낮은 MIDI, 높은 MIDI]), showSteps(반음 번호를 보일지)
- 흰건반·검은건반 SVG. 기준음 건반에 점, 위 음 건반은 색으로 강조. 건반 색은 두 테마에서 같은 값.
- showSteps면 기준음 다음 건반부터 위 음까지 1, 2, 3 … 작은 동그라미 숫자. 위 음 숫자만 진하게.
- 위 음 이름표는 건반 위, 기준음 이름표는 아래(NoteName 사용). 위 음에 임시표가 있는데 흰건반에 닿으면 "건반은 D 자리" 같은 글.
- MIDI는 엔진 midiOf, 범위는 엔진 keyboardRange.
/lab/의 7개 악보 아래에 각각 건반을 붙여 줘(3도는 keyboardRange([3]), 5도는 keyboardRange([5]), showSteps=true).
```

**확인 방법** — `/lab/`
- C–E♭: C에 점, 검은건반 E♭ 강조, 숫자 1·2·3.
- C–E𝄫: 흰건반 D가 강조되고 "건반은 D 자리". 숫자 1·2.
- B–F𝄪(5도): 맨 오른쪽 G 건반 강조, 숫자 1~8. 3도 건반은 E까지(흰건반 10개), 5도 건반은 G까지(12개).

**확인 방법** — `/lab/`

## 6단계 — 둘러보기 화면

**프롬프트**
```text
자유 둘러보기 화면 src/app/explore/page.tsx를 만들어 줘. 기획서 4-10절, 5-2절 배치, prototype.html과 같은 모양.

- 위 막대: ← 홈 / "자유 둘러보기"
- 층 표시판, 왼쪽 건물, 오른쪽 악보 + 도수 세기 칸(C·D·E처럼 기준음 문자부터 도수만큼, 엔진 degreeLetters) + 안내 칸 + [차례로][함께],
  아래 건반, 맨 아래 [▼ 한 층 아래로][▲ 한 층 위로] (끝층이면 꺼지고 이유: "건물의 맨 위층이에요"/"위층은 아직 잠겨 있어요").
- 바꿔 보기: 건물(3도/5도), 기준음(C~B 7개). 지금은 모두 열어 두고(열린 층 = buildingFloors), 11단계에서 잠금을 붙인다.
- 건물을 바꾸면 그 건물의 기준층(3도 2층 장3도, 5도 1층 완전5도 — 엔진 referenceFloor)으로 간다.
- 안내 칸 문장(둘러보기 전용, 화면에서 만든다):
  · 이동 뒤: "{이전 이름} → {지금 이름}" / "위 음 {이전 위 음} → {지금 위 음}" / "악보 자리는 그대로, 소리만 반음 위로(아래로)"
  · 기준음을 바꾼 뒤: "기준음 {X}" / "{도수 세기 글자} {N} 칸 → 위 음 자리 {Y}" / 지금 층의 "{층} {이름}: {X}–{위 음}"
  · 처음: "한 층 = 반음 하나" / "아래 버튼으로 한 층씩 움직여 보세요"
- 키보드 ↑↓로도 이동.
- 듣기 버튼은 지금은 눌러도 아무 일 없게 두고 7단계에서 소리를 붙인다.
- 미션 화면에서 다시 쓸 수 있게 화면 조각(위 막대, 표시판, 악보 칸, 안내 칸, 아래 버튼줄)을 부품으로 나눠 줘.
- 폰 세로 화면에서 위 막대부터 아래 버튼줄까지 650px 안에 들어오게.
```

**확인 방법** — `/explore/`
- 시안(`docs/prototype.html`)과 나란히 열었을 때 배치가 거의 같다.
- 5도 건물, 기준음 C, 1층에서 한 층 위로: 위 음 G → G♯, "증5도 · 8반음". A♭으로 바뀌지 않는다 (기획 PDF 예시 B).
- 기준음 D, 3도 1층: D–F 단3도 (임시표 없음). 한 층 위로 → D–F♯ 장3도.
- 폰에서 보기: "같은 와이파이의 폰에서 볼 수 있게 개발 서버를 켜 줘"라고 하면 주소(예: `http://192.168.0.12:3000/explore/`)를 알려 준다. 가로로 밀리지 않고 아래 버튼까지 보이는지 본다.

## 15단계 — 배포 (GitHub → Vercel)

**프롬프트**
```text
배포 준비를 해 줘.
- README.md에 앱 소개, 실행 방법(npm install, npm run dev, npm test, npm run build), 폴더 구조를 쉽게 적어 줘.
- .gitignore 확인(node_modules, .next, out, _kit).
- npm test, npm run build 통과 확인 후 커밋.
- 내가 GitHub Desktop과 Vercel에서 눌러야 할 순서를 알려 줘.
```

**직접 하는 일** (화면 이름은 바뀔 수 있음)
1. GitHub Desktop: File → Add Local Repository… → `interval-elevator` 폴더 선택 → 위쪽 [Publish repository] → 이름 확인, Keep this code private는 원하는 대로 → Publish.
2. Vercel(vercel.com) 로그인 → Add New… → Project → Import Git Repository에서 방금 올린 저장소 [Import] → Framework Preset이 Next.js인지 확인 → [Deploy].
3. 배포가 끝나면 나오는 주소를 폰으로 연다. 설정 > 선생님용의 수업 링크가 이 주소로 만들어진다.

**확인 방법**
- 배포 주소에서 1-0부터 진행된다. 새로고침(특히 `/stage/1/` 같은 주소에서)해도 404가 나지 않는다.

## 막혔을 때 쓰는 프롬프트

**오류가 날 때**
```text
아래 오류가 났어. 원인을 쉽게 설명하고 고쳐 줘. engine.ts와 정답표는 고치지 마.
(오류 내용 붙여 넣기)
```

**엔진 검사(npm test)가 실패할 때**
```text
npm test에서 엔진 검사가 실패했어. engine.ts·정답표·테스트 파일은 고치지 말고,
어떤 검사가 왜 실패하는지, 최근에 무엇을 바꿔서 그렇게 됐는지 먼저 알려 줘.
```

**화면이 시안이나 기획서와 다를 때**
```text
[화면 주소]의 [부분]이 docs/prototype.html(또는 기획서 [절])과 다르게 보여. [어떻게 다른지].
시안·기획서처럼 맞춰 줘.
```
(가능하면 폰 화면을 캡처해서 함께 붙여 넣는다.)

**폰에서 화면이 밀리거나 잘릴 때**
```text
폰([기종], [브라우저])에서 [화면 주소]가 가로로 밀려(또는 [부분]이 잘려). 360px 폭에서도 가로 스크롤 없이 보이게 고쳐 줘.
```

**아이폰에서 소리가 안 날 때**
```text
아이폰([iOS 버전])에서 소리가 안 나. 기획서 6장대로 첫 터치 때 AudioContext resume과 navigator.audioSession.type = 'playback'이
되는지 확인하고, 소리 켜기 상태와 무음 스위치 상태별로 어떻게 동작하는지 정리해 줘.
```

**되돌리고 싶을 때**
```text
마지막 커밋 상태로 되돌려 줘. 되돌리기 전에 무엇이 사라지는지 먼저 알려 줘.
```

## 규칙을 바꾸고 싶을 때

미션의 문제 수, 기준음, 안내 문장, 별 기준 같은 규칙은 엔진(`src/engine/engine.ts`)에 있다. 엔진을 바꾸면 정답표도 함께 바꿔야 검사가 통과한다. 이 경우에만 아래처럼 분명히 허락하고 지시한다.

```text
규칙을 바꾸고 싶어: [예: 2-1 층 맞히기 문제 수를 6에서 8로 / 1-0 안내 3번째 대사를 "…"로].
1) 기획서의 해당 절을 먼저 고치고,
2) src/engine/engine.ts에서 그 부분만 바꾸고,
3) npx tsx scripts/make-golden.ts 로 정답표를 다시 만들고,
4) 정답표에서 바뀐 부분이 내가 말한 변경뿐인지 git diff로 확인해서 요약해 줘,
5) npm test, npm run build 통과 확인 후 커밋해 줘.
이번에는 engine.ts와 정답표를 고쳐도 돼.
```
